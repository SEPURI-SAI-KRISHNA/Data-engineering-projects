# Contributing

Thank you for taking the time to contribute. Contributions of all kinds are welcome — bug fixes, documentation improvements, new project ideas, and corrections to existing projects.

## How to contribute

1. **Fork** the repository and create your branch from `main`.
2. **Make your changes.** Keep each pull request focused on a single concern.
3. **Test your changes.** Each project has its own test instructions in its `README.md` or `DESIGN.md`. Ensure existing tests still pass.
4. **Open a pull request** with a clear description of what you changed and why.

## Guidelines

- **Stay truthful.** Do not document behaviour that isn't implemented. If you're adding a feature, add it; if you're updating docs, match them to the code.
- **Keep projects self-contained.** Each sub-project should remain independently runnable after your change.
- **Respect the existing style.** Match the code style, naming conventions, and level of documentation detail already present in the sub-project you're editing.
- **Explain design decisions.** Significant architecture or algorithm choices belong in the project's `DESIGN.md`, not just in commit messages.

## Reporting issues

If you find a bug, a misleading explanation, or an improvement opportunity, open a GitHub Issue with:

- which project it affects
- a minimal reproduction or a clear description of what you expected vs what happened

## Code of conduct

Be constructive and respectful. This is a learning-focused repository and all skill levels are welcome.
